# Project Character

Status: active portfolio-governance note
Class: **C — Exploratory / Learning-Led**

## Governing principle

```text
Learning, experimentation and demonstrated understanding may shape the solution.
External assignment constraints and safety boundaries remain fixed.
```

This repository is primarily a course and portfolio learning artifact rather than an operator-critical personal product.

## Fixed constraints

The project must continue to respect:

- the explicit course deliverables and evidence requirements;
- secure treatment of Azure, SQL, storage and identity credentials;
- no real secrets committed to Git;
- truthful documentation of what is and is not deployed or proven;
- bounded cloud cost and explicit operator approval for paid resources;
- no weakening of authentication, authorization or data protection merely to complete a demo.

## Exploratory freedom

DON and engineering may have broad freedom to:

- compare implementation alternatives;
- refactor the Flask application;
- improve deployment, logging, authentication and testing;
- add learning notes and architecture explanations;
- choose the order of technical experiments;
- reject obsolete course defaults when a safer current method is documented and still satisfies the learning objective.

## Product evolution

Unlike an Intent-Locked project, the exact UI, internal architecture and demonstration flow may evolve as learning occurs.

A change still requires operator approval when it:

- creates or changes paid Azure resources;
- exposes the application publicly;
- introduces credentials or personal data;
- materially changes the course submission target;
- broadens the repository into a production service.

## Success

Success is demonstrated understanding and reproducible evidence, not production-scale completeness.
